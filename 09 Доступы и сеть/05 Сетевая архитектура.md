# Сетевая архитектура — целевая схема
```mermaid
flowchart TB
 U[Пользовательский VLAN] --> FW[МЭ / ACL — точка Т1]
 V[Удалённый сотрудник] --> VPN[VPN-шлюз + MFA]
 VPN --> FW
 FW --> WEB[A2 Портал / серверная зона]
 WEB --> ARC[A1 Архив]
 ADMIN[Админские АРМ + EDR] --> JUMP[Защищённый узел управления]
 JUMP --> FW
 FW --> SVC[Разрешённые серверные интерфейсы]
 PHONE[Голосовой VLAN] --> PBX[IP-АТС]
 PBX --> SIP[SIP-транк оператора]
 BAK[A5 Копии и ключи] --- ARC
 FW -.сетевые события.-> LOG[A4 Сборщик]
 WEB -.аудит операций Т2.-> LOG
 ARC -.аудит Т2.-> LOG
 VPN -.входы.-> LOG
 ADMIN -.EDR.-> LOG
 PBX -.регистрации и вызовы.-> LOG
 BAK -.состояние копий.-> LOG
 LOG --> SIEM[SIEM / правила]
 SIEM --> SOC[Аналитик / группа 5]
```
Пунктир — **события**, сплошная стрелка — логически разрешённое взаимодействие. Связь архива с резервными копиями не означает открытый двусторонний сетевой доступ.

## Границы доверия
1. Внешняя сеть ↔ VPN/пограничные сервисы.
2. Пользовательский VLAN ↔ серверная зона.
3. Административная зона ↔ узел управления ↔ серверы.
4. Голосовой VLAN ↔ IP-АТС/оператор.
5. Рабочие системы ↔ изолированное хранение резервных копий.

Запретить транзит между пользовательским и административным сегментами по умолчанию. На МЭ хранить правила с владельцем, назначением, сроком и заявкой.
