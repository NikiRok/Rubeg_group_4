# Справочник идентификаторов — межгрупповой канон

> Статус: **нумерация F согласована по предложению группы 3 на уровне документации группы 4; содержательные изменения требуют подтверждения владельцев**. Технические таблицы описывают целевую модель, а не доказанную фактическую конфигурацию.

| Префикс | Назначение | Основной источник | Статус |
|---|---|---|---|
| F | Сетевые потоки | [[06 Матрица сетевых потоков]] | F01–F16; F01–F12 сохранены |
| D | Правила наблюдаемости / SIEM | [[18 Матрица наблюдаемости и правила SIEM]] | D01–D10 сейчас; D11 и сквозная перенумерация — в согласовании |
| DET | Рабочие правила обнаружения | [[03 Мониторинг/Правила обнаружения]] | DET-01–DET-07; нужны ссылки на D |
| C | Приёмочные тесты | файл 11 (уточнить путь) | C01–C10; C11 предложен, не подтверждён |
| AUD | Замечания аудита | реестр 02 (уточнить путь) | Нумерация и ссылки подлежат сверке |
| K | Контроли в xlsx | лист «03 Контроли» | Не смешивать с тестами C |

## Канонические дополнительные потоки

- F13 — USER → A1 напрямую: запрет.
- F14 — VPN подрядчика → A1/A5: запрет.
- F15 — ADMIN/утверждённый jump host → управление IP-АТС: разрешить только уполномоченному админу IP-АТС.
- F16 — SOC → A4: только чтение.
- Общий ADMIN → MGMT не получает отдельный F-ID без решения групп 2/3; нельзя считать его автоматически разрешённым.

- [ ] **Группа 3:** F12 — размещение агента T03 на A1/A2 и направление копирования.
- [ ] **Группа 5:** D11 «успешный вход после отказов», таблица соответствий DET→D и критерий потери источника без фиксированного пятиминутного порога.
- [ ] **Группы 2 и 5:** права SOC на метаданные аудита A1 и неизменяемость журналов A4.
- [ ] **Группа 1:** критичность A1–A6 и предварительные оценки риска P×I.
- [ ] **Группы 1 и 3:** EDR на АРМ — привязка к A6 по общему реестру; перечень затрагиваемых файлов и xlsx.
- [ ] **Группы 1 и 3:** разделение RTO архива и последующей сверки временного журнала.

## Правило изменений

Любое новое значение ID сначала вносится в основной реестр, затем обновляются ссылки в остальных файлах, сценариях и xlsx. Запрещено использовать один ID для разных смыслов. Отсутствие подтверждения отмечать как «требует согласования», а не как «выполнено».

## Вопросы для передачи по группам

### Группа 1 — владельцы и риски
- [ ] Утвердить критичность A1–A6; не считать все активы автоматически «высокими».
- [ ] Подтвердить предварительную оценку рисков P×I и владельцев риска; до этого указывать «не оценён».
- [ ] Согласовать отнесение административных АРМ/EDR к A6 по общему реестру.
- [ ] Утвердить критерий RTO 60 минут до возобновления доступа к архиву; последующая сверка временного журнала — отдельная проверка приёмки.

### Группа 2 — режим доступа
- [ ] Подтвердить права подрядчика: F05, доступ только к назначенному узлу, через jump host или иной путь по архитектуре; согласование, MFA, срок, отзыв.
- [ ] Утвердить временные именные административные сессии F06/F07/F15 и разделение полномочий на A4/A5.
- [ ] Определить SOC: допустим ли только просмотр метаданных аудита A1, без доступа к содержимому.
- [ ] Уточнить, может ли подрядчик администрировать IP-АТС и кто контролирует такие работы.
- [ ] Подтвердить проверки прав при A2→A1 (F03) и правила отзыва прав при переводе/увольнении.

### Группа 3 — архитектура и сценарии
- [ ] Подтвердить F05 через jump host, путь управления коммутатором и МЭ, необходимость отдельного ADMIN→MGMT.
- [ ] Подтвердить F12: агент T03 на A1/A2, инициатор соединения и граница A5.
- [ ] Сверить исходную формулировку временного правила USER→ADMIN, не менять факт карточки.
- [ ] Согласовать номера тестов C, контролей K и замечаний AUD, включая C10/C11 и ссылки сценариев.
- [ ] Проверить различие проектной матрицы F и фактической конфигурации.

### Группа 5 — SOC/SIEM
- [ ] Утвердить D11, соответствия DET→D и необходимые события от F08/F16.
- [ ] Для контроля потери логов выбрать критерий по ожидаемой частоте событий/heartbeat и критичности источника, **без общего порога 5 минут**.
- [ ] Согласовать обязательные поля события, сроки хранения, эскалацию и доступ SOC только на чтение.

**Правило:** решения группы 4 не подменяют утверждение владельца соответствующей области. Не отмечать вопрос согласованным до явного ответа группы.
